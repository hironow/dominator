# `.pass/` Directory Structure

Dominator manages all state under `<repo-root>/.pass/`.
This document describes what each directory/file does, who creates it, and how it flows into the judgment pipeline.

## Directory Tree

```
.pass/
  .gitignore            # auto-managed by init command
  config.yaml           # target, NFR thresholds, load config
  k6-scripts/           # k6 load test scripts (session-authored via mcp-k6)
    load-test.js
    ...
  insights/             # git-tracked insight ledger
    hue.md              # judgment history (pass/violation)
    coefficient.md      # deviation details per judgment
  skills/
    dmail-sendable/
      SKILL.md          # agent skill manifest (phonewave discovery)
    dmail-readable/
      SKILL.md
  inbox/                # incoming D-Mails
    *.md
  outbox/               # outgoing D-Mails (picked up by phonewave)
    *.md
  archive/              # permanent D-Mail audit trail
    *.md
  events/               # append-only event log (JSONL, daily rotation)
    2026-03-15.jsonl
    ...
  .run/                 # ephemeral runtime projections
    plans/              # execution plans (JSON)
    latest.json         # latest judgment state
```

## Git Tracking Rules

The repo-root `.gitignore` manages `.pass/` tracking with individual entries:

```
.pass/.run/
.pass/events/
.pass/inbox/
.pass/outbox/
.pass/archive/
```

| Path | Git Status | Reason |
|------|-----------|--------|
| `config.yaml` | Tracked | Project-level configuration (shared across clones) |
| `k6-scripts/` | Tracked | Session-authored test scripts, kept for reproducibility |
| `insights/` | Tracked | Judgment history ledger |
| `events/` | Ignored | Append-only event log (single source of truth) |
| `skills/` | Ignored | Agent capability manifests (regenerated by `dominator init`) |
| `.run/` | Ignored | Ephemeral projections (rebuildable from events) |
| `outbox/` | Ignored | Transient; courier picks up and delivers |
| `inbox/` | Ignored | Transient; consumed and archived on check |
| `archive/` | Ignored | D-Mail audit trail |

## Insight Ledger

The `insights/` directory contains git-tracked Markdown files that summarize judgment results.

### hue.md

Records the overall judgment history. Each entry represents a single judgment run:

```markdown
## 2026-03-15T14:30:00Z — pass

Script: load-test.js, VUs: 10, Duration: 30s
All NFR thresholds met.
```

Analogous to the Psycho-Pass hue: consistently clear entries indicate a healthy system. Clouded entries (violations) signal degradation.

### coefficient.md

Records detailed deviation tables per judgment:

```markdown
## 2026-03-15T14:30:00Z — violation

| Metric | Threshold | Actual | Deviation | Severity |
|--------|-----------|--------|-----------|----------|
| p95_latency_ms | 500.00 | 750.00 | 50.0% | high |
| error_rate_percent | 1.00 | 2.50 | 150.0% | high |
```

Analogous to the Crime Coefficient: the specific metrics that caused the judgment to flag a violation.

## Event Sourcing Architecture

All state mutations flow through the event store, which appends events as JSONL entries with daily file rotation.

### Event Types

| Event Type | Triggered By | Description |
|---|---|---|
| `script.generated` | `generate` command (retired stub) | k6 script created from API spec (historical events) |
| `generation.failed` | `generate` command (retired stub) | Script generation error (historical events) |
| `plan.created` | retired `check` command | Execution plan created (legacy; kind kept registered for ledger replay) |
| `plan.approved` | retired `approve` command | Plan approved (legacy; kind kept registered for ledger replay) |
| `judged` | `run` command | Judgment result recorded |
| `violation.detected` | `run` (violation) | NFR threshold exceeded |
| `pass.confirmed` | `run` (pass) | All NFRs within thresholds |

## D-Mail Lifecycle

```
[External tool]          dominator                    [External tool]
     |                      |                              |
     | writes to inbox/     |                              |
     |--------------------->|                              |
     |                      | inbox command                |
     |                      |   parse -> archive/ (copy)   |
     |                      |   remove from inbox/         |
     |                      |                              |
     |                      | (judgment runs, D-Mail generated)
     |                      |                              |
     |                      | EmitViolation / EmitPass:    |
     |                      |   -> outbox/                 |
     |                      |                              |
     |                      |              reads outbox/   |
     |                      |----------------------------->|
```

On violation, three D-Mails are emitted (design-feedback, implementation-feedback, verification-feedback). On pass, a single nfr-pass report is emitted.

## D-Mail File Format

```yaml
---
name: design-feedback-20260315T143000Z
kind: design-feedback
description: "NFR violation: 2 deviation(s) detected"
severity: high
---

# NFR Violation Report

Plan: abc123
Script: load-test.js, VUs: 10, Duration: 30s

| Metric | Threshold | Actual | Deviation | Severity |
|--------|-----------|--------|-----------|----------|
| p95_latency_ms | 500.00 | 750.00 | 50.0% | high |
```

| Frontmatter Field | Type | Required | Description |
|-------------------|------|----------|-------------|
| `name` | string | Yes | Unique identifier (`{kind}-{timestamp}`) |
| `kind` | string | Yes | `design-feedback`, `implementation-feedback`, `verification-feedback`, or `report` |
| `description` | string | Yes | One-line summary |
| `severity` | string | No | `high`, `medium`, or `low` |

## File Creators

| File | Created By | When |
|------|-----------|------|
| `.pass/` dirs | `init` command | `dominator init` |
| `config.yaml` | `init` command | Init (only if absent) |
| `k6-scripts/*.js` | `generate` command | Script generation |
| `events/*.jsonl` | `FileEventStore.Append` | On each state mutation |
| `.run/plans/*.json` | legacy plan files (writer retired with `check`) | retired `check` command |
| `insights/hue.md` | `InsightWriter.RecordHue` | After judgment |
| `insights/coefficient.md` | `InsightWriter.RecordCoefficient` | After judgment |
| `outbox/*.md` | `DMailEmitter` | Violation or pass |
| `inbox/*.md` | External tool (courier) | Before inbox processing |
